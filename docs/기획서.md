## 1. 서비스 명칭

**분쟁72** (해외 AI·클라우드·구독 결제 이상청구 대응 비서)

"이상한 해외결제를 발견한 뒤 첫 72시간"에 해야 할 일을 정해 주고, 카드사 이의신청 서류까지 만들어 주는 웹서비스입니다.

## 2. 아이디어 기획 핵심내용(요약)

- 한국은 해외 AI 서비스 유료 결제가 가장 빠르게 늘어난 나라입니다. 국내 생성형 AI 월 구독 결제액은 2024년 1월 34억 원에서 2025년 12월 803억 원으로 2년간 2,361% 늘었고, 넷플릭스 월평균 구독료(750억 원)를 넘어섰습니다. (한국경제, 2026-01-18)
- 그런데 이 결제에서 문제가 생기면(해지 후 청구, 중복 승인, API 키 유출로 인한 고액 청구, 청구 금액 오류) 소비자는 두 개의 낯선 절차를 동시에 겪습니다. 영어 티켓 기반의 해외 사업자 고객센터, 그리고 국제브랜드 규정을 따르는 카드사 이의신청입니다. 금감원은 해외결제 분쟁 처리에 3~5개월이 걸리고, 거래일로부터 90~120일 안에 증빙을 갖춰 신청해야 한다고 안내합니다. (금융감독원, 2026-06-09)
- 분쟁72는 카드 알림 문자, 청구 메일, 상황 설명(또는 캡처 사진)을 받아 **3단계로 대응을 준비**합니다.
  - **진단**: 이상 신호 탐지(급증·중복·해지 후 청구·미승인 사용량·승인 거절 반복), 카드 문자의 가맹점 표기 해독(예: `STRIPE *GAMMAAI` → 결제대행, 실제 판매자 GammaAI), 발신 도메인 확인, 원문 인용 기반 사실 정리
  - **72시간 계획**: 지혈(0~2시간) → 가맹점 환불 요청(24시간) → 카드사 준비(72시간). 사건 유형·결제 상태·카드사에 따라 절차가 바뀌고, 120일 참고 기한을 계산
  - **이의신청 패키지**: Visa·Mastercard 사유코드 후보, 증빙 체크리스트와 준비도, 카드사 9곳의 접수 채널·기한·서류 안내, 신청서 항목 미리 채우기, 영문 문의·국문 사실 정리·타임라인 초안
- 핵심 설계 원칙은 **"규칙은 데이터, 이해와 작문은 AI"** 입니다. 카드사 절차·사유코드·사업자 환불 정책·당국 안내는 출처와 조회일이 붙은 데이터로 두고, 생성형 AI는 비정형 입력을 사실로 구조화하고 초안을 쓰는 데만 씁니다. AI 판단에는 반드시 근거 조각을 인용하게 하고, 원문에 없는 인용·코드·기한은 코드가 걸러냅니다.
- 배포 URL에서 예시 사건 3종은 AI 호출 없이 바로 열리고, 실제 입력은 OpenAI Responses API로 분석합니다. 발송과 접수는 사용자가 직접 결정합니다.

## 3. 문제 정의 및 제안 배경

### 3-1. 현재 금융 서비스의 구체적인 문제

**(1) 결제는 늘었는데 대응 도구가 없습니다.**
ChatGPT, Claude, Gemini 같은 AI 구독과 AWS·Google Cloud·OpenAI API 같은 사용량 과금은 대부분 해외 사업자에게 카드로 직접 결제됩니다. 한국은 ChatGPT 유료 구독에서 세계 2위 시장이고, 생성형 AI 사용자 증가 속도는 조사 대상 30개국 중 1위입니다. (한국경제, 2026-01-18) 결제 규모가 커지면 오결제·이상청구도 같이 늘어납니다. 금감원에 접수된 신용카드 민원은 2022년 6,720건에서 2025년 12,661건으로 4년간 88.4% 늘었고, 금감원은 2026년 6월 해외결제 분쟁을 첫 번째 유의 사례로 꼽았습니다. (머니투데이, 2026-06-09)

**(2) 소비자는 절차를 두 개 동시에 모릅니다.**
- 사업자 단계: 영어 티켓, 봇 응대, 정책 문서가 흩어져 있음. OpenAI·Perplexity처럼 한국 거주자의 7일 청약철회를 명시한 곳도 있지만 소비자는 알기 어렵습니다.
- 카드사 단계: 국제브랜드 규정에 따라 사유코드별 증빙이 다르고, 카드사마다 기한 안내가 다릅니다(KB국민카드 승인일로부터 110일, BC카드 전표 접수일로부터 75~120일, 금감원 안내 90~120일). 처리에는 2~4개월(KB), 최장 6개월(우리카드)이 걸립니다.
- 금감원은 "증빙(주문내역·영수증·판매자와의 메일·채팅)을 충분히 확보한 뒤 신속히 이의제기"하라고 권고하지만, 무엇을 어떻게 확보하라는지는 소비자 몫입니다.

**(3) 사용량 과금은 기존 차지백 체계가 상정하지 않은 유형입니다.**
구독은 "해지했는데 청구됐다"로 끝나지만, API 키 유출은 "내가 쓰지 않았다"를 소비자가 증명해야 합니다. 사용 로그는 사업자가 갖고 있고, 카드 자체가 도용된 것이 아니라서 카드 도용 사유코드(Visa 10.4, Mastercard 4837)도 맞지 않습니다. 키 유출로 하루 약 1,000달러가 청구된 사례가 OpenAI 개발자 커뮤니티에 보고돼 있습니다(2026-06). 이 유형은 사업자의 미승인 사용 검토가 1차 경로인데, 소비자는 그 사실 자체를 모릅니다.

**(4) 가맹점 쪽은 이미 AI로 방어합니다.**
Chargeflow, Justt 같은 서비스는 가맹점 편에서 사유코드별 반박 증빙 패키지를 AI로 자동 생성해 제출합니다. 소비자 편에는 같은 도구가 없습니다.

### 3-2. 고객과 채널을 이렇게 고른 이유

**고객: 카드로 해외 AI·클라우드·SaaS를 직접 결제하는 개인.** 개발자, 1인 창업자, 대학(원)생, 프리랜서가 핵심입니다. 이들은 은행 창구에 가지 않고, 문제를 발견한 밤에 혼자 검색하다가 포기하거나 카드 전체를 정지시키는 최후 수단부터 씁니다. 2026년 공모전 주제 예시 중 "이상금융거래 탐지 시 맞춤형 행동 요령을 제공하는 AI 금융 보안 비서"와 정확히 겹치는 고객군입니다.

**채널: 모바일 대응 웹.** 이 고객이 가진 1차 증거는 카드 알림 문자와 청구 메일이고, 둘 다 붙여넣기나 캡처로 옮길 수 있습니다. 그래서 첫 화면을 "카드 문자 / 청구 메일 / 내 상황" 세 슬롯과 사진 첨부로 설계했습니다. 금감원이 권고하는 "카드결제 알림 서비스"가 만들어 낸 문자를 그대로 입력으로 씁니다. 확장 채널은 카드사·은행 앱의 해외승인 알림 옆 버튼입니다(6장).

## 4. 서비스 컨셉 및 차별성

### 4-1. 컨셉: "사건 접수증"

화면은 승차권 형태의 사건 티켓입니다. 상단 티켓에 사건 제목, 가맹점, 금액, 거래 상태, 카드사, 참고 기한이 찍히고, 아래로 진단 → 72시간 계획 → 이의신청 패키지 → 연결 보드 네 탭이 이어집니다. 72시간 계획은 열차 시간표처럼 0~2시간, 24시간, 72시간, 120일 노드로 표시되고, 패키지의 마지막은 절취선 아래 스텁(사건 번호, 사유코드 후보, 증빙 준비도, 참고 기한)으로 끝납니다. 말투는 토스 UX 라이팅 원칙을 따라 짧은 해요체로 통일했습니다.

### 4-2. 기존 금융 앱·서비스와의 차별성

| 비교 대상 | 하는 일 | 분쟁72와 다른 점 |
|---|---|---|
| 카드사 앱의 해외이용 이의신청 | 접수만 받음 | 접수 전 단계(무엇이 문제인지, 증빙은 무엇인지, 가맹점에 먼저 뭘 보내야 하는지)를 소비자에게 맡김. 분쟁72는 그 앞 단계를 채움 |
| 일반 AI 챗봇 | 일반론 답변 | 카드사 9곳 절차, 사유코드 14개, 사업자 18곳 정책을 출처와 함께 내장. 근거 없는 코드·기한은 쓰지 못하게 제한 |
| 구독 관리 앱(왓섭 등) | 국내 구독 해지 대행 | 해지 이후의 "청구 분쟁" 영역. 해외 사용량 과금을 다룸 |
| 소비자원 국제거래 소비자포털 | 정적 안내, 번역 템플릿 | 내 사건에 맞게 동적으로 조합. 소비자포털의 120일·45일 규정을 인용해 연결 |
| 가맹점용 차지백 자동화(Chargeflow 등) | 가맹점 편 증빙 패키지 | 같은 방식을 소비자 편에서 구현 |

### 4-3. 무엇이 진짜 "동작"하는가

1. **탐지·해독**: 카드 문자를 규칙 파서가 먼저 읽어 카드사, 승인 유형, 통화·금액, 일시, 가맹점 표기를 확정합니다. 표기는 정책 사전 18곳에 대조해 실제 사업자와 공식 창구, 환불 조건, 해지 규칙을 붙입니다. 사진을 올리면 글자를 옮겨 적은 뒤 같은 절차를 탑니다.
2. **절차 엔진**: 사건 유형(6종) × 결제 상태(5종) × 카드사(9곳)에 따라 72시간 계획과 증빙 체크리스트가 바뀝니다. 매입이 없는 사건은 이의신청 대신 "반복 시도 차단 상담"으로 바뀌고, 카드사를 고르면 그 카드사의 접수 채널·기한·사유 이름이 계획과 신청서에 들어갑니다.
3. **근거 인용**: AI 판단 요약 아래에 최대 4개의 근거가 사유코드·사업자 정책·카드사 절차·당국 안내 칩으로 붙고, 각 칩은 출처 URL로 연결됩니다.
4. **안전장치**: 전송 전 개인정보 마스킹 확인, 국외·국제발신 문자 경고, 프롬프트 주입 방어(입력 속 지시 무시), 원문에 없는 인용 자동 제거, 발송·접수 미대행.

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

### 5-1. 활용 데이터

| 데이터 | 내용 | 수집·활용 방식 |

| 당국·기관 안내 | 금감원 2026-06 유의사항, 소비자원 차지백 가이드(120일·45일), 국제거래 소비자포털, 표준약관 14일 이의 조항 | 출처 URL과 함께 인용 |
| 카드 문자 패턴 | 승인 유형·통화·금액·일시·가맹점 표기 정규식 | 규칙 파서. 카드사별 샘플 확보 시 정밀화 |

모든 데이터는 `data/` 아래 JSON으로 두고, 항목마다 출처 URL과 조회일(2026-09-06)이 붙어 있습니다. 서비스는 이 데이터를 화면에 그대로 보여주고, 생성형 AI에도 같은 조각을 넘깁니다.

### 5-2. 생성형 AI 적용 방안

모델은 OpenAI Responses API(`gpt-5.6-sol`)를 Zod Structured Outputs로 호출합니다. 한 사건에 최대 세 번 호출합니다.

| 호출 | 역할 | 입력 → 출력 | 제어 장치 |
|---|---|---|---|
| ① 옮겨 적기 (사진이 있을 때만) | 캡처 속 글자를 보이는 그대로 텍스트로 | 이미지 → 줄 단위 텍스트 | 요약·추측 금지, 이미지 속 지시문 무시, 결과는 마스킹 후 원문에 이어 붙임 |
| ② 사실 추출 | 비정형 텍스트를 구조화 | 텍스트 → 제목, 요약, 가맹점·표기, 유형, 결제 상태, 금액, 거래일, 신호, 사실(원문 인용) | 규칙 파서가 읽은 값을 "확정 값"으로 주입. 원문에 없는 인용은 코드가 제거. 연도 없는 날짜는 비움 |
| ③ 판단·초안 | 사실과 근거 조각을 대조해 판단 | 사실 + 규정·정책 조각 → 판단 요약, 근거(refId), 질문 3개, 행동 3개, 경로, 영문 문의·국문 사실 정리·타임라인 | 근거 id는 제공한 조각 안에서만. 조각에 없는 코드·기한·환불 조건 생성 금지. 카드 도용 코드 자동 매핑 금지 |

**생성형 AI가 맡지 않는 것**: 사유코드 결정, 기한 계산, 카드사 절차, 증빙 체크리스트, 가맹점 해독. 이것들은 정답이 있는 영역이라 데이터와 규칙이 맡습니다. 그래서 심사자가 어떤 입력을 넣어도 절차 부분은 흔들리지 않고, AI는 "이 사건이 어떤 사건인지 읽고, 무엇을 물어보고, 어떻게 써 보낼지"에 집중합니다.

**말투와 인용**: 모델 출력도 화면과 같은 해요체로 쓰되, 카드사 제출용 사실 정리와 영문 메일은 문서체를 유지하도록 프롬프트에 규정했습니다.

## 6. 기대 효과 및 확장 가능성

### 6-1. 해결하는 문제와 기대 효과

- **소비자**: 문제를 발견한 밤에 무엇부터 할지 정해집니다. 키 삭제·한도 설정·해지 확인처럼 돈이 더 나가는 걸 막는 조치가 첫 2시간에 오고, 가맹점 환불 요청 초안이 24시간 안에 나가며, 카드사 접수는 증빙과 사유가 맞춰진 상태로 준비됩니다. 120일 기한을 놓치는 일이 줄고, 3~5개월짜리 카드사 왕복이 줄어듭니다.
- **금융회사**: 30% 넘게 늘어난 카드 민원 중 해외결제 건을 접수 전에 정리합니다. 사유·증빙이 맞춰진 접수는 콜센터 상담 시간과 국제브랜드 재접수를 줄입니다.
- **시장**: 가맹점만 쓰던 AI 증빙 자동화를 소비자도 쓰게 됩니다.

### 6-2. 확장 방안

1. **카드사·은행 앱 임베드**: 해외승인 알림 옆 "이 결제 이상해요" 버튼에서 분쟁72 흐름을 열면, 사용자는 이미 로그인된 카드 정보와 매입 여부를 갖고 시작합니다. 공동개최사(하나은행, 신한은행, 카카오뱅크)가 곧 접점입니다.
2. **마이데이터 연동 탐지**: 카드 승인·매입 내역을 연동하면 "평소 대비 급증"을 통계로 계산해 알림 단계에서 먼저 잡습니다. 지금은 사용자 입력 기반 신호 탐지까지 구현했습니다.
3. **회신 해석 루프**: 가맹점 답장을 붙여넣으면 AI가 "환불 약속·거절·추가 자료 요청"으로 읽고 계획을 자동으로 갱신합니다. 재분석과 변경점 표시는 이미 있고, 회신 유형 판정만 붙이면 됩니다.
4. **사례 데이터 축적**: 익명화 사건을 모으면 가맹점별 평균 환불 소요일과 성공 패턴이 데이터가 됩니다.

### 6-3. 타 영역 응용

같은 구조(입력 → 규칙 파서 → 데이터 대조 → 근거 인용 초안)는 해외직구 미배송·환불 분쟁, 항공·숙박 취소 분쟁, 국내 구독 다크패턴, 스타트업의 클라우드 비용 이상 탐지에 그대로 옮길 수 있습니다. 바뀌는 것은 데이터 파일뿐입니다.

## 7. 안전과 신뢰를 위한 설계 (자유 항목)

- **개인정보**: 전송 전 마스킹 결과를 사용자가 보고 수정한 뒤 보냅니다. 사진은 자동 마스킹이 되지 않는다는 점을 명시하고, 옮겨 적은 글은 서버에서 마스킹합니다. 대화 저장(`store`)을 끄고, 사건 저장은 사용자가 원할 때 브라우저에만 7일 보관합니다.
- **보안**: 입력 속 지시문은 자료로만 취급하도록 프롬프트에 경계를 두고, 국외·국제발신 문자는 스미싱 경고를 띄웁니다. 공개 URL에는 IP별 호출 제한을 두었습니다.
- **정직한 표시**: 참고 기한은 확정이 아니라 "참고치"로, 사유코드는 "후보"로, 카드사 절차는 확인 수준 배지(공식 확인 / 일부 확인 / 2차 자료 / 이용자 경험)와 함께 보여줍니다. 미리 만든 예시는 "예시" 도장으로 구분합니다.
- **한계**: 카드사 실제 접수, 마이데이터 연동, 자동 발송은 하지 않습니다. 결과는 검토용이며 환불 권리나 신청 기한을 확정하지 않습니다.
